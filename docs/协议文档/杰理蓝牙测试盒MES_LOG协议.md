# 杰理蓝牙测试盒 MES LOG 协议

> **一句话**：杰理蓝牙测试盒经串口按 `CRC16 | LEN | MASK | LTV*` 主动上报 LOG，供 MES / 上位机解析蓝牙地址、频偏、RSSI 等。  
> **读者**：产测上位机开发、治具/产线工程师。  
> **前提**：测试盒已按 §2 接线与拨码/配置开启对应输出；上位机实现见 `agreement/fixture_protocol/jieli_bt_box/`。  
> **来源**：厂商「测试盒 MES LOG 输出功能」说明整理；CRC 细节另见 [报文CRC计算说明.md](./报文CRC计算说明.md) §7。

---

## 快速参考

| 项 | 值 |
|----|-----|
| 方向 | 测试盒 → 上位机（被动上报，无问答指令） |
| 波特率 | **460800** |
| 帧格式 | `CRC16(2) \| LEN(2) \| MASK(4) \| {L,T,V}*`，均小端 |
| CRC | CRC16-XMODEM，覆盖 **LEN + body**（不含 CRC 自身） |
| 上位机入口 | `JieliBtBoxDevice::waitForRfInfo` / `JieliBtBoxCodec` |
| 工站步骤 | 「解析蓝牙信号强度和频偏」（`WaitRfInfo`） |
| 产测常用字段 | T=1 MAC、T=7 频偏、T=8 RSSI |

## 2. 接线与模式

### 2.1 接线

- LOG 输出走测试盒串口，波特率 **460800**。
- EDR 连接模式与 BLE 测试使能下的物理接线以厂商手册接线图为准（拨码不同时接线位置可能不同）。

### 2.2 模式与拨码（重要）

| 条件 | 行为 |
|------|------|
| 拨码 **6「ble 测试」不为 ON** | EDR 连接模式：仅做 EDR 连接相关 LOG |
| 拨码 **6「ble 测试」为 ON** | 仅 BLE 连接；默认可输出**蓝牙地址** |
| 拨码 **6 为 ON** 且拨码 **4「频偏测试」为 ON** | 才会输出**频偏**与 **RSSI**（T=7 / T=8） |

产测「解析蓝牙信号强度和频偏」依赖 T=7 + T=8：现场必须 **BLE 测试 + 频偏测试** 同时打开，否则上位机长时间收不到合法频偏/RSSI 帧会超时。

LOG 输出前需在测试盒侧开启相关配置（名称以厂商 UI 为准）：

|--------|------|------|

| 对耳配对使能 | 勾选 | 输出配对状态 / 配对后地址（T=5 / T=6） |

## 4. 帧格式

```
             |<------------- LEN --------------->|
 +--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+
 |CRC16| LEN |    MASK   |L |T |V....|L |T |V....|
 +--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+
       |<---------------- CRC16 ---------------->|
```

| 字段 | 长度 | 说明 |
|------|------|------|
| CRC16 | 2 | 小端；对 **除 CRC16 自身外**的整段（即 LEN 起至帧尾）做 CRC16 |
| LEN | 2 | 小端；`MASK(4) + 全部 LTV` 的字节数 |
| MASK | 4 | 小端 `u32`；每位对应一种数据类型，见 §5 |
| LTV | 变长 | 可重复；`L`=`V` 长度，`T`=类型，`V`=载荷 |

**组帧关系**：`MASK` 中某 BIT 置 1 ⇒ 帧内应出现对应 `T` 的 LTV（顺序通常按类型编号递增，以实测为准）。

上位机实现约定（与厂商一致）：CRC 算法为 **CRC16-XMODEM**（多项式 `0x1021`、初值 0）。当前 codec 在 CRC 不匹配时仍尝试抽帧（仅打日志），因实测部分帧算法不一致；**LEN 与 TLV 结构必须合法**，否则整包丢弃。

---

## 5. MASK 位定义

| BIT | 数据类型 | 说明 |
|-----|----------|------|
| 0 | 左右耳 | `0` 左耳，`1` 右耳；标记在 MASK 内，不单独占 LTV |
| 1 | 蓝牙地址 | 串口模式勾选测试使能时输出 → T=1 |
| 2 | SDK 版本 | EDR 下勾选连接显示 SDK 信息 → T=2 |
| 3 | CRC32 | EDR 下勾选电量及校验码 → T=3 |
| 4 | 电量 | 同上 → T=4 |
| 5 | 配对状态 | 勾选对耳配对使能 → T=5 |
| 6 | 配对后的蓝牙地址 | 同上 → T=6 |
| 7 | 频偏 | BLE + 频偏测试 → T=7 |
| 8 | RSSI | BLE + 频偏测试 → T=8 |
| 9 | 频偏校准结构 | → T=9 |

---

## 6. LTV（L / T / V）

| T | 数据类型 | V 长度 | 说明 |
|---|----------|--------|------|
| 1 | 蓝牙地址 | 6 | MAC，原始 6 字节 |
| 2 | SDK 版本 | 32 | 字符串区（可含 `0x00` 填充） |
| 3 | CRC32 | 4 | |
| 4 | 电量 | 1 | 十六进制一字节 |
| 5 | 配对状态 | 1 | `0` 未配对，`1` 已配对 |
| 6 | 配对后的蓝牙地址 | 6 | |
| 7 | 频偏 | 4 | 小端 **int32** |
| 8 | RSSI | 4 | 小端 **int32**（单位 dBm，可为负） |
| 9 | 频偏校准结构体 | 4 | 见下表 |

### 6.1 T=9 频偏校准结构体

```c
struct fre_offset_t {
    u8 flag;                 // 0:未校准; 1:本次校准; 2:已校准
    s8 bf_trim_fre_offset;   // 校准前频偏
    s8 trim_fre_offset;      // 校准后频偏
    u8 fre_offset_result;    // 校准结果（与测试盒「最大频偏提醒」勾选项对比）
};
```

共 4 字节，与 `L=4, T=9` 对应。

## 7. 示例

### 例1：仅蓝牙地址

```text
2F C0 0C 00 03 00 00 00 06 01 08 C5 EE 4B 0B 87
```

| 字段 | 值 |
|------|-----|
| CRC16 | `2F C0` |
| LEN | `0C 00` = 12 |
| MASK | `03 00 00 00`（BIT0+BIT1） |
| LTV | `06 01` + `08 C5 EE 4B 0B 87`（MAC） |

### 例2：地址 + SDK + CRC32 + 电量 + 配对

```text
CE 8A 42 00 7E 00 00 00 06 01 E9 FE 53 86 9A 52
20 02 ...（32 字节 SDK）...
04 03 13 E7 54 75 01 04 64 01 05 01 06 06 A0 E3 B1 6D 9A EB
```

| 字段 | 值 |
|------|-----|
| CRC16 | `CE 8A` |
| LEN | `42 00` = 66 |
| MASK | `7E 00 00 00`（BIT1～BIT6） |

### 例3：地址 + 频偏 + RSSI（产测常用）

```text
19 50 18 00 83 01 00 00 06 01 8C 4C 80 7A A0 C2
04 07 1B 00 00 00 04 08 CD FF FF FF
```

| 字段 | 值 |
|------|-----|
| CRC16 | `19 50` |
| LEN | `18 00` = **24** |
| MASK | `83 01 00 00`（BIT0+BIT1+BIT7+BIT8） |
| T=1 | MAC `8C 4C 80 7A A0 C2` |
| T=7 | 频偏 `1B 00 00 00` → **27** |
| T=8 | RSSI `CD FF FF FF` → **-51** |

注意：合法「地址+频偏+RSSI」帧的 **LEN 应为 `18 00`（24）**，不是任意值。若串口收到类似 payload 但 LEN 字段错误，上位机 `tryExtractFrame` 会判定结构非法并丢弃。

## 8. 与上位机实现的对应关系

| 文档 | 代码 |
|------|------|
| 整帧解析 | `jieli_bt_box_codec.cpp` → `tryExtractFrame` / `parseFrame` |
| T 枚举 | `JieliBtBoxCodec::TlvMac=1` … `TlvFreqCalib=9` |
| 等待上报 | `JieliBtBoxDevice::waitForRfInfo`（默认要求 **同时有** T=7 与 T=8） |
| 步骤指令 | `JieliBtBoxCmd::WaitRfInfo`（`jieli_bt_box_cmd_manifest`） |
| 串口 | 工位「产品串口(仪器)」，波特率默认 460800（可 SETTINGS 覆盖） |
| 卡控 | 步骤 ini `[Gate]`：`rssi` / `freqOffset` |

当前 codec **已识别** T=1～9 枚举，但 `waitForRfInfo` 业务路径主要消费 **频偏 + RSSI**（及日志中的 MAC）；SDK/电量/配对等字段若 MASK 带出，解析时跳过未知业务逻辑即可。

## 9. 验证

1. 拨码：BLE 测试 ON + 频偏测试 ON；MES LOG 配置置 1。  
2. 上位机打开产品串口 460800，跑「解析蓝牙信号强度和频偏」。  
3. 后台日志期望依次出现：  
   - `JIELI_BT_BOX RX: …`  
   - `JIELI_BT_BOX OK freq=… rssi=…`  
4. 对照例3：LEN=`18 00`，且存在 `04 07 …` 与 `04 08 …`。

失败时优先看：拨码是否缺频偏测试、LEN 是否与 body 长度一致、是否只有 RX 无 OK（抽帧失败）。

## 10. 常见问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 超时「等待杰理频偏/RSSI 上报」 | 拨码 4 未开，无 T=7/8 | 打开频偏测试 |
| 有 `JIELI_BT_BOX RX` 无 `OK` | LEN 与 TLV 对不齐，或帧不完整 | 对照 §7 例3 查 LEN；抓完整帧 |
| 仅有 MAC、无频偏/RSSI | 仅 BLE 开、频偏测试关 | 见 §2.2 |
| 频偏值为 `FF FF FF FF`（-1） | 测量未完成或无效占位 | 查射频/时机/盒子状态；即使字段存在，业务卡控也可能失败 |
| CRC 日志告警仍能 OK | 实现允许 CRC 不匹配仍抽帧 | 以 LEN+TLV 合法性为准；仍建议核对盒端固件 |
