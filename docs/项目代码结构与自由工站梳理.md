# 项目代码结构与自由工站梳理

> 本文梳理整个上位机工程的代码文件职责，重点展开「自由工站」（`work_station/freework/`）。
> 面向新人 onboarding 与改动前快速定位，不涉及具体协议字节级细节（协议细节见 `docs/协议文档/` 与 `docs/开发参考资料/`）。

---

## 1. 项目概述

- **定位**：多工站产测上位机（FCT/ATE），Qt 5.15.2 + MSVC2019 编写。
- **核心思想**：**配置驱动**。测试步骤不硬编码在代码里，而是由 INI「功能块（test case）」动态编排，因此能适配任意产线流程，这也是「自由工站」得以存在的基础。
- **分层依赖**（自上而下，避免反向 include）：

```
UI / 工站  →  SerialChannel / QProtocolManager / 平台服务  →  具体协议实现
```

## 2. 编译与启动

### 2.1 编译配置（`new_production.pro`）

- 工程入口文件，同时承担「模块开关」职责。顶部定义一组 `ENABLE_STATION_*` 宏，默认全部为 `0`：

```
ENABLE_STATION_MOTOR_TEST / IMU_CALI / SCREEN_TEST / CAMERA_TEST /
WIFIBLE_TEST / PRESS_TEST / PCBA_TEST / QUIESCENT_CURRENT /
AGE_TEST / KEY_TEST / SUCTION_TEST = 0
```

- 这些宏通过 `DEFINES += ENABLE_STATION_XXX=...` 传入编译，工站源文件在 `.pro` 里用 `equals(ENABLE_STATION_XXX, 1) { ... }` 条件编入。
- **自由工站没有宏开关，始终编译**（`qfreework*.cpp` / `shared_instrument.cpp` 直接列在主 SOURCES 中）。
- 改宏后须**重新 qmake**（否则预编译头与 DEFINES 不一致，会出现 C4651）。

### 2.2 启动流程（`main.cpp`）

`main.cpp` 用 `switch` 根据启动模式选择要运行哪一个工站箱子（box），每个分支的模式一致：

```cpp
case 10: {
    QFreeWorkBox* f = new QFreeWorkBox; // 自由工站
    f->show();
    f->TotallyTask();
    delete f;
    break;
}
```

- `case 11` 是主测试 `MainWindow`，`case 12` 是 `factory_analyzer`，其余 case 是各专用工站（按键/吸力/压感/PCBA 等）。
- 启动前还有 `login_dialog`（登录）与 `test_case_sync_service`（测试用例云端同步）等前置逻辑。

## 4. 工站框架的三层类

```
box_base  (QMainWindow)   ← 工站容器（一拖 N 箱子）
   └─ QFreeWorkBox         ← 自由工站容器

test_base (QWidget)        ← 单工站公共基类
   └─ QFreeWork            ← 自由工站（本文重点）
```

### 4.1 `box_base`（`work_station/box_base.h/.cpp`）

工站容器的公共基类：

- `QList<test_base*> testList`：一个箱子管理的所有工站 widget。
- `CreatWindow<WidgetType>()`：按 `formRow × formColumn`（从 `SETTINGS` 读取）动态创建网格布局，实现「一拖 N」。
- 负责 MES 登录、设置窗口、窗口尺寸/状态恢复、`checkStateReady`（整机联动）、`TotallyTask`（总任务）。
- 静态入口：`tryRunSingleTestCaseStepOnAnyFreeWork`（设置页右键单步调试）、`refreshFlowUiOnAllFreeWork`。

### 4.2 `test_base`（`work_station/test_base.h/.cpp`）

所有工站的公共底座，**持有并暴露几乎所有通讯与业务依赖**：

- **协议管理器成员**：`QProtocolManager protocolManager`、`QModbusManager modbusManager`、`QScpiManager scpiUsbManager_/scpiVisaManager_`、`QatManager* at`，以及 `Qpb/Qfctp/Qaiot/Qroot` 各协议对象。
- **串口通道**：dongle / usb / jig / product 四路 `SerialChannel`，以及对应的打开/关闭/扫描/收发帧槽。
- **虚接口**：
  - 工站流程：`startTask()`（纯虚）、`startTest/endTask/useMes`；
  - 控件桥接：`getMacLineEdit()/logEdit()/msgEdit()/testResultTable()/getComNameCombo()...`（子类 override 返回自己的 UI 控件，供基类通用逻辑操作）；
  - 协议上行虚槽：几十个 `refreshXxx(ProtocolXxxData)`，由 `onProtocolReport` 按 reportType 分发，子类按需 override。
- **通用工具**：
  - `sendCommandWithRetry`：指令发送 + 等待回包 + 超时重试 + 应答来源限定（`CommandWaitSource`）的核心机制；
  - `testResultTableUpdate/updateTestData`：结果表刷新与 MES 测试值汇总；
  - `parseMacFromSn / validateSnFormat / applyAdaptiveV3ProductBySn`：SN/MAC 处理；
  - `finishTestRecord`：测试结束本地入库 + 云端上报 + MES 过站。

## 5. 自由工站 `QFreeWork` 详解

### 5.1 定位

「自由」= 测试步骤不写死，按工站 `flow.ini` 配置的功能块顺序执行，因此一套 UI/逻辑可适配任意产线。自由工站是当前产线的主力工站（`main.cpp` 中 `case 10`，且**始终编译**）。

### 5.2 类声明结构（`qfreework.h`，486 行）

`class QFreeWork : public test_base`，`friend class QFreeWorkTestCaseHookRegistrar` 与 `TestCaseRunner`。

成员按职责分组（节选自头文件注释）：

| 分组 | 关键成员 | 说明 |
|---|---|---|
| UI 桥接 | `getMacLineEdit()/logEdit()/...` override | 把自己的 `ui->xxx` 暴露给基类 |
| test_case 对外接口 | `useTestCaseFlow / setActiveTestCase / evaluateActiveTestCaseGate / markActiveTestCaseStepDone` | 功能块运行态查询与推进 |
| 运行态结构体 | `TestCaseStepResult`、`StepRuntime` | 单步完成状态、计时、testData/ask |
| 扫描/绑定 | `snBinding / wholeMachineSn_ / mesProcessCode_` | SN、整机 SN、BYD SFC 过程码 |
| RSSI/WiFi/电量/电流 | `BT_RSSI / WIFI_RSSI / HighCurrent / voltage ...` | 测试数据暂存 |
| 有序测试队列 | `orderedTestCaseNames_ / orderedFailCaseNames_ / runningFailFlow_` | 主流程 + 失败执行区 |
| 弹窗/按键等待 | `keyWaitPrompt_ / testCasePrompt_ / freeWorkKeyWaiting_` | 按键测试、弹窗确认步 |
| 业务门面 | `plcFacade_ / cmwFacade_` | `business/` 层门面（PLC/CMW100），工站只调度命令 |
| 产品串口/仪器 | `productInstConn_ / lastBrushInstrumentProfile_` | CMW100 蓝牙 PER/RX 步骤 |
| 三元组/BYD | `tupleData_ / freeWorkMesSegments_ / huilingVisaLinkCache_` | 三元组写入、MES 分段、会凌 VISA 缓存 |
| 吸力采样 | `suctionPeakTargetKpa_ / suctionPlot_ / dongleSuctionCh*Samples_` | Dongle 吸力峰值采样与曲线 |
| 共用外设 | 走 `shared_instrument.h` 命名空间 | 一拖多 VISA/温度仪通道映射 |

### 5.4 测试用例数据模型（`platform/test_case/`）

这是自由工站的「引擎」，核心数据结构在 `test_case_types.h`：

```
TestCaseDefinition {
    TestCaseMeta   meta;              // name / displayName / mesTag / promptEnabled / promptText
    TestCaseSend   send;              // Channel + 协议 + 指令 + 参数
    TestCaseTiming timing;            // delayBefore/AfterMs / commandTimeoutMs / waitReply
    TestCaseGate   gate;              // 主卡控（Range/Gt/Lt/Eq/CompareVersions）
    QVector<TestCaseGate> gates;      // 多字段卡控
    TestCaseHook   hook;              // 钩子
}
```

`send.channel` 枚举（决定走哪条执行通道）：

```
Product | ProductSerial | Dongle | Cloud | Fixture | Modbus | Scpi
```

配套 `test_case.h` 的类（`test_case.cpp` 实现）：

| 类 | 职责 |
|---|---|
| `TestCasePaths` | 路径（steps 库 / profiles 工站目录 / flow.ini / case.ini） |
| `TestCaseStore` | INI 读写、工站目录、flow 编排（Items/FailItems/StopFlowOnTestFail/SerialUi/DeviceSide） |
| `TestCaseValidator` | case 校验、流程内 MES 字段唯一性校验 |
| `*CmdCatalog` | 指令枚举 ↔ INI 字符串互转（Device/Dongle/Asd9026a/Xwd/JieliBtBox/FixturePcba/ProductSerial/Modbus/Scpi/Tuple） |
| `GateRegistry` | 卡控判定与展示 |
| `TestCaseHookRegistry` | 钩子注册/分发 |
| `TestCaseRunner` | 执行辅助（是否需异步完成、是否 BLE 连接步、是否弹窗确认步等） |

### 5.5 执行链路

自由工站跑一轮的主流程：

1. `box_base::CreatWindow` 按网格创建 N 个 `QFreeWork`；
2. `QFreeWork::startTask()`（override `test_base` 纯虚）→ `runTestFlowBootstrap()`；
3. `tickOrderedTestStepLoop()` 依 `orderedTestCaseNames_` 逐步骤推进；
4. 每步：`TestCaseRunner::beginStep` → `setActiveTestCase` → 按 `send.channel` 分发到对应 `execute*` → 等回包（`sendCommandWithRetry`）→ `evaluateActiveTestCaseGate`（卡控）→ `markActiveTestCaseStepDone` → 下一步；
5. 特殊步骤走钩子：`TestCaseHookRegistry::invoke` → `QFreeWorkTestCaseHookRegistrar::dispatch`；
6. 任一步失败且 `StopFlowOnTestFail=true` 时，转跑 `orderedFailCaseNames_`（失败执行区）。

### 5.6 钩子机制（`qfreework_case_hooks.cpp`）

当某个功能块无法用「发指令 + 回包卡控」表达时（如纯等待、主动采样、写入 SN 等），通过 `Hook/HookId` 走钩子。

`registerAll()` 幂等注册全部 HookId，`dispatch(fw, hookId)` 用 if-链分发。已注册钩子一览：

| HookId | 作用 |
|---|---|
| `JIG_CURRENT_READ` | 读取治具电流测量值 |
| `DONGLE_SUCTION_ENABLE/DISABLE/SAMPLE/SAMPLE_SINGLE` | Dongle 吸力采样开关与采样 |
| `SN_WRITE_TAIL` | 写入尾号 SN |
| `PRINT_WHOLE_MACHINE_SN` | 打印整机 SN |
| `QR_SN_CONSISTENCY_CHECK` | 二维码/SN 一致性校验 |
| `COUNTDOWN_WAIT` | 倒计时等待 |
| `MES_GET_ROOT_SKU` | 从 MES GetCustomData 取 ROOTSKU |
| `MAC_WRITE_ROOT` | 写入 MAC |
| `PLC_MODBUS_CONN` | PLC Modbus 连接测试 |
| `PLC_V3_SWITCH_RIGHT_WHOLE` / `PLC_V3_SWITCH_DONE_RESET_M` | PLC 旋钮/复位 |
| `PLC_V3_KEY_MODE/PROGRAM/SPEED/RIGHT/START_PAUSE/LEFT/POWER` | PLC 按键 |
| `PROD_INST_RESET_ACK` / `PROD_INST_START_RX_*` / `PROD_INST_STOP_RX_PER` | CMW100 蓝牙 PER/RX 仪器步骤 |

> 注：纯按键等待已改为步骤 Gate（`ProtocolButtonStateData` + `Expected`），不再走旧的 `KEY_*` / `KEY_M8_*` Hook。

### 5.7 卡控机制（`GateRegistry`）

- 回包经 `test_base::onProtocolReport` 按 `reportType` 分发到 `refreshXxx` 后，自由工站用 `evaluateActiveTestCaseGate(reportType, payload)` 做判定。
- `GateRegistry::evaluate/evaluateAll` 支持 Range / Gt / Lt / Eq / CompareVersions，上下限可引用 `LowSettingsKey/HighSettingsKey` 从 SETTINGS 读。
- 多字段卡控（如杰理 RSSI/频偏）用 `gates` 列表，全部通过才算过，结果表/MES 按分项对齐（`emitFixtureMultiGateTableRows` / `appendMultiGateTestCaseMes`）。
- `$MAC/$SN` 等占位符在判定前由 `applyRuntimePlaceholderGateExpected` / `applyRuntimeSnGateExpected` 展开。

### 5.8 共用外设（`shared_instrument.cpp`）

解决「两个工位共用一台外设」的场景，全部由步骤 `Param` 配置（不读上位机设置）：

- `sharedPair=true` + `stationsPerDevice=N`：一拖多映射；
- 程控电源：`visaAddress0/1` + `scpiChannelSelectCmd` 选通通道；
- 温度记录仪：`channelsPerStation` + `tempComName0/1`，`tempChannelListForStation` 按工位映射通道（工位1→CH1-6，工位2→CH7-12）。
