# 上位机版本发布流程规范

> **主线 `develop` → `-p`；其他分支 → `-d`。**  
> 上传需 admin、已登录工厂云；`BaseUrl` 指向目标环境。

## 1. 版本号怎么管

| 项 | 规则 |
|----|------|
| 后缀 | `develop` 用 `x.y.z-p`；其余分支用 `x.y.z-d` |
| 运行时版本 | 存在 **`上位机设置.local.ini`** → `FactoryCloud/HostAppVersion` |
| 编译默认 | `my_set/host_ota_version.h` 的 `HOST_OTA_APP_VERSION`（local 为空时写入） |
| 改号入口 | 帮助 → **检查更新** → **修改本地版本**（上传前也会再确认） |
| `buildId` | 编译自动生成 `yyyyMMdd-HHmmss`，**勿手改** |
| 不改 | 工站 `XXX_VER` / `AbIni.h`（与 OTA 无关） |

```text
develop     → 1.6.37-p   （正式发版可升基线，仍 -p）
其他分支    → 1.6.36-d   （合入 develop 后改为 -p）
```

禁止：无后缀的纯 `x.y.z`；非主线写 `-p`；主线长期留 `-d`。

## 2. 发版步骤

```text
1. 确认分支 → 定 -p / -d，必要时在「检查更新」里改本地版本
2. Release 编译：.\scripts\编译Release版本.ps1 -SkipQmake
3. 本机自测
4. admin → 帮助 → 检查更新 → 上传当前版本（必填修改说明）
5. 产线 / 内测：检查更新 或 选择版本 → 安装抽测
```

- 仅本机自测：可不上传。  
- 特性分支给产线验证：用 `-d` 上传即可；合入主线后再发 `-p`。  
- 同日多次上传：重新编译即可（`buildId` 会变大）。  
- 「检查更新」按云端最大 `buildId` 取包（不区分 `-d`/`-p`）；要指定某一包用「选择版本」。

## 3. 入口与路径

| 项 | 值 |
|----|-----|
| 本地版本 | `上位机设置.local.ini` → `FactoryCloud/HostAppVersion` |
| 编译默认 | `my_set/host_ota_version.h` |
| 上传 | 帮助 → 检查更新 → 上传当前版本 |
| 网页 | 工厂云管理端 → 上位机版本 |
| 生产 BaseUrl | `https://fctp.luteos.com` |

## 4. 产线升级（简）

无在测产品 → 检查更新（或选择版本）→ 确认安装 → 抽测。强制升级时勿强杀进程。
